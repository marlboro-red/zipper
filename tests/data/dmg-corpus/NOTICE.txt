Every image here was written for Zipper's tests by hdiutil on macOS 26
and then compressed with `xz -9`. No file in them comes from a third party.

The hfsplus and hfsx images hold one volume each, HFS+ named Corpus and
case-sensitive HFS+ (HFSX) named Sensitive. Each was made as an 8 MiB
read-write UDIF image, mounted under a scratch folder, filled with `ditto`
from a generated folder and with `ditto --hfsCompression` for its
`compressed` folder, detached, and converted with `hdiutil convert -format`:

| Image | Format | Chunks |
| --- | --- | --- |
| hfsplus-udzo.dmg, hfsx-udzo.dmg | UDZO | zlib |
| hfsplus-udbz.dmg | UDBZ | bzip2 |
| hfsplus-ulfo.dmg, hfsx-ulfo.dmg | ULFO | LZFSE |
| hfsplus-ulmo.dmg | ULMO | xz |
| hfsplus-udro.dmg | UDRO | raw |
| hfsplus-udco.dmg | UDCO | ADC |

The generated folder holds small text files, 5,000 seeded random bytes,
names in Latin, CJK and emoji letters, a symlink, a file with three hard
links, a folder 40 levels deep, a folder of 300 files, and files with
modes 755, 444 and 600 in a folder of mode 555. `ditto --hfsCompression`
stored `big.txt` and `noise.bin` as LZVN chunks in their resource forks and
`medium.txt` as LZVN data in its decmpfs attribute.

sparse-6g-udzo.dmg holds a 6 GiB HFS+ volume. A 4,400 MiB file of zeros
was written and then deleted after `far.txt` was written behind it, so that
file lies past 4 GiB in a partition that is mostly zero chunks.

`trees.json` holds the tree Zipper extracts from each image, which
`tests/dmg_corpus.rs` checks against `7zz x` 26.05 where it is installed.
An image whose tree equals an earlier one's names that image.
`ZIPPER_DMG_WRITE_TREES=1 cargo test --test dmg_corpus` rewrites it.
