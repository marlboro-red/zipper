Every volume here was written for Zipper's tests on macOS 26 by `mkntfs`
from ntfs-3g 2026.9.28 and filled by `tools/ntfs_build.c`, a small program
that links libntfs-3g from the same release, then compressed with `xz -9`.
`tools/make_corpus.py` holds the commands for every volume. No file in them
comes from a third party, and no volume comes from Windows.

ntfs-3g was built from its Homebrew source with `--disable-ntfs-3g
--enable-ntfsprogs --disable-crypto`, since its FUSE driver needs Linux.
The library and tools are under the GPL and LGPL, and none of their code is
in Zipper or in these volumes.

| Volume | What it holds |
| --- | --- |
| ntfs3g-basic.ntfs | resident and stored files, an empty file, three hard links, a DOS name, Unicode names, a read-only file, set times, a deleted file, 400 files in one folder and 24 nested folders |
| ntfs3g-compressed.ntfs | LZNT1 folders of text, random bytes, one unit and one chunk |
| ntfs3g-fragmented.ntfs | four files written in turn, 1 KiB clusters, so two have attribute lists and extension records |
| ntfs3g-links.ntfs | relative, parent, absolute and junction reparse points |
| ntfs3g-sparse.ntfs | sparse files, with a compression unit and no compression flag |
| ntfs3g-streams.ntfs | a named stream `Zone.Identifier` |
| ntfs3g-512-clusters.ntfs | 512-byte clusters with a compressed folder and a hard link |
| ntfs3g-4096-sectors.ntfs | 4096-byte sectors and records, with update sequence entries every 512 bytes |

`trees.json` holds the tree Zipper extracted from each volume when it was
written, as SHA-256 per file, which matched the tree `7zz x` 26.05 extracted
apart from the differences in `docs/reference/ntfs-reader.md`. `ntfscat`
from the same ntfs-3g release read every regular file Zipper wrote outside
`[SYSTEM]` to the same bytes. `ZIPPER_NTFS_WRITE_TREES=1 cargo test --test
ntfs_corpus` rewrites it from Zipper's own extraction, which the same test
compares with 7-Zip where it is installed.
